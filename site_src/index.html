the problem

Federated learning is invisible.

The data never leaves the clients. That's the point. But it also means that while a run is going, all you see is a log. Which client was slow? Which layers moved? Who failed, and did the round carry on? The log doesn't say.

how to use it

Add three lines. Change nothing else.

client_app.py

from flwr_viz import viz_mod
app = ClientApp(mods=[viz_mod])

server_app.py

from flwr_viz import instrument
strategy = instrument(FedAvg(...), run_config=context.run_config)

terminal

flwr-viz serve        # then open http://127.0.0.1:7878

Works with any model, dataset and ML framework, and with any Flower strategy: FedAvg, FedProx, FedMedian, Krum, or your own.

An app that runs its own loop with no strategy at all just instruments its grid:
grid = instrument(grid, ...)

Built for Flower 1.44, using the Message API. Flower itself is not modified.

how it works

Four small parts.

Client mod

Wraps every message a client handles: when it arrived, how long the job took, the metrics, and per-layer summaries of the model in and out.

Strategy wrapper

Wraps any strategy from outside: which clients were picked, every message and reply, failures, timeouts, and how the global model changed.

Collector

A tiny server that receives the events over the network, records every run to a file, and streams them to browsers.

Browser

The 3D scene you see on this page. It rebuilds everything from the events, so live view, scrubbing and replay are the same thing.

Sending never blocks training: if the collector is down, events are quietly dropped. Only summary numbers travel (sizes and changes per layer), never weights or data.

reading the scene

Everything has a shape.

Clients are characters

Their shirt colour is their state, and their pose shows what they're doing.

idleselectedtrainingevaluatingworkingsendingdonefailed

The server is the diamond

It floats in the middle, spins and glows while it merges the clients' updates, and flashes when a new global model is ready.

Messages are paper planes

Blue planes carry the model out. Orange planes carry updates back. Red means something failed.

A model is a stack of books

One book per layer. Wider means more numbers; the colour shows how much that layer changed.

Big federations become towers

When the clients don't fit on one ring, floors stack downwards. Hundreds of clients stay smooth.

Click anyone

A beam rises from their head into a card with everything known about them. Hover anything on the card for a plain-language explanation.

learn mode

Learn it by answering questions.

Press learn in the viewer. The run pauses and asks you something; you answer by clicking in the scene; then that part of the run plays and is explained with its real numbers.

Each app needed two lines plus their imports. Everything they exposed was fixed in the plug-in, never for one app:

  • apps with no strategy are recorded at the grid level
  • the Flower version is no longer pinned (it broke installs on Python 3.10)
  • layers are matched when a message carries extra records
  • errors show their root cause, not a wrapper
  • serialized byte payloads are no longer treated as numbers
  • custom job types keep their own names and charts

privacy

It keeps the promise federated learning makes.

Sent (by default)

  • timing and message flow
  • the metrics the app already returns
  • per layer: size, shape, and how much it changed

Never sent

  • weights or gradients
  • training data or labels
  • config values, partition ids
  • tracebacks

Your choice

  • minimal: only timing and flow
  • hide layer names
  • a shared token for the collector
  • off

where it stands

What works, and what's not proven yet.

Verified

  • simulation runs with 5 different apps and 5 strategies
  • every recording replays exactly, with no federation running
  • a dead collector doesn't slow training
  • 300 clients render in about 7–12 ms a frame
  • 53 automated tests

Not verified

  • real deployments across machines
  • Flower versions other than 1.44
  • a successful XGBoost run
  • Firefox and Safari

Next

  • publish the package so apps don't need a local path
  • an in-browser sandbox: change the strategy and see what happens
